## The verification ledger, round 9

**1. The falsifiers came first — all seven of the audit's obligations, as batteries or checker rules.** GPT's round-9 brief enumerated what a maintenance engine must survive before it may consume warrants; each item was implemented as a falsifier before the engine was trusted, and one (receipt completeness) promptly earned its keep against this record's own checker (item 6 below).

**2. The enabling refactor: queries read through an interface.** Atomicity (falsifier 6) wants fork-and-apply — a pass computing on a *forked* world, committing only if whole. Forking was impossible while scope queries captured world references (`publishWarrant`'s freshness closures read the world they were registered on — a fork's scopes would have consulted the wrong world). Scope functions now receive a reader interface (`{value, version, names, scope}`) and touch nothing else, making `World.fork()` total: copied byte-entries, copied vclock and log, copied *pure* query functions. All fourteen prior batteries re-ran green through the refactor before any maintenance code existed.

**3. The Maintainer: classification drives action, dependencies first, once each.** A pass computes a **deterministic topological order** (Kahn, sorted ready-set) over the maintained DAG and visits each node exactly once, citees before citers: `fresh` → replay-*validate* (the only moment footprint versions permit replay — a refusal **quarantines**); `support_intact` → refresh (early cutoff, escalating to re-derive on value divergence); `support_changed`/`scope_dirty` → re-derive; every action republishes on the fork so downstream freshness scopes see current citees. L-MAINT-1 asserts the order from the receipt itself, the convergence (every publication FRESH after one pass), the values (A=2, B=3, C=30 after the ground moved), and that B's new footprint cites A's *new* publication — then keeps the **wrong-order counterfactual red**: C re-derived before A carries the wrong value *and* is detectably non-fresh once A lands. A citer refreshed against a stale citee cannot be current, and now that's a battery, not a design note.

**4. Quarantine at both doors; diamonds once; cycles proved absent; failure discards the fork.** L-MAINT-3: the support-forged warrant is refused at `register()` (`support-mismatch`) *and*, when poisoned directly into maintainer state, quarantined in-pass — publication untouched, ids unchanged in the step record; forged input is never repaired in place or propagated. L-MAINT-4: the diamond `D←{B,C}←A` yields exactly four steps — A once, not once per path — with **identical `pass_id`s across identical runs**: the receipt is reproducible, not narrative. L-MAINT-5: forward references are impossible via the API (cites must exist), and the pass *independently proves* acyclicity by Kahn leftover — a two-cycle poisoned directly into the defs refuses the whole pass, names `[X, Y]`, and moves nothing. L-MAINT-6: A re-derives on the fork, then B's measure throws — the fork is discarded and the real world's publications, vclock, and maintainer state are byte-identical to before; the receipt records `{aborted, at: B}` with the completed steps for forensics. Nothing half-advanced.

**5. The receipt proves the pass — before + steps must reconstruct after.** `TRVM-MAINTPASS-v1` commits the vclocks, the **before and after publication maps** (`{pub_version, warrant_id}` per name), and the ordered steps; `no_op` is *recomputed*, not asserted (all-none steps ∧ vclock unmoved ∧ before == after — L-MAINT-2 proves the second pass at quiescence is exactly that). grid_check v2.9 performs the reconstruction engine-free: each step's before/after fields must agree with the maps; `none`/`quarantined` must not move the publication; `refreshed`/`rederived` must advance it and reseal; the no-op flag must recompute. This was the item GPT flagged as the next round-5 danger zone, and it was built as arithmetic on arrival.

**6. The negative battery caught the checker within minutes — and the fix is the law's own point.** The `maint-step-erased-resealed` forgery (delete step B, honestly reseal the commitment) **passed grid_check v2.9's first draft**: reconstruction iterated over *steps*, verifying each against the maps, but never required the maps to be *covered by* steps — B's moved publication sat in before/after with no step accounting for it. The coverage rule is now **bidirectional**: every step names a known publication, and — for a completed pass — every publication is named by exactly one step ("receipt hides publication B" is the diagnostic); partial (aborted/refused) passes may omit steps only for publications that provably did not move. Falsifier 7 was aimed at the engine and hit the auditor first, which is precisely what the negative battery is for. One more self-catch recorded: L-MAINT-1's first draft contained an ORed junk clause of exactly the `|| true` species the audit found last round — caught in skeptical re-read before shipping, replaced with both halves asserted.

**7. Gate.** Twenty world batteries green (fourteen priors through the refactor + L-MAINT-1..6), `--check-receipt` green, maintenance receipt deterministic across runs, grid v1.5.0 — 44 entries / 294 citations, κ green, negative battery **39/39** with four maintenance-receipt forgeries each on a distinct diagnostic. Kernel frozen at v1.0.2, untouched for the fourth consecutive round.

## Theory movement this round

**Maintenance is classification made executive.** Rounds 7–8.2 built verdicts with witnesses; round 9 gives the verdicts consequences — and every consequence is gated by re-derivation (validate, refresh, re-derive) rather than trust, so the trichotomy's economics (cheap refresh vs forced re-derivation) become an actual scheduler, receipted.

**A pass is a transaction over publications.** Fork-and-apply makes the maintenance pass atomic in exactly the database sense, and the receipt's reconstruction rule makes it *serializable evidence*: old state + committed steps ⇒ new state, checkable by arithmetic with no engine in sight. The two verifier modes stay honest about their split: grid_check proves the bookkeeping; the engine proves the derivations.

**Next:** CP5–CP7 via the kernel's module interface — kernel-computation warrants whose witnesses are semantic films, unifying the two portable evidence objects and giving "canonicalization interleaved with world transition" its first executable surface; mechanically derived support (the grid's declared v4 question) now that maintenance consumes the classification; and ic32, whose protocol surfaces have grown to four: semantic films, warrants, composition, and receipted maintenance passes.

## Round 9.1 — the fork was a convention; now it is a boundary

**8. GPT falsified fork-and-apply as stated, and both halves of the witness reproduced exactly.** `AUDIT-FORK-ESCAPE` against v0.5.0 (frozen in `probe_forkescape_v05_repro.mjs`): a `measureFn` that retained the authoritative World wrote it mid-pass and threw — the "aborted" pass had moved the real vclock 3→4 and left the leaked resource, so **`ATOMIC = false`**. Nastier still: the abort path sampled `this.world.vclock` *in the catch handler*, so the receipt reported `vclock_before: 4` — **the escaped transition normalized into the receipt's alleged pre-state**, invisible as a transition anywhere. The audit's diagnosis is adopted verbatim: the actual v0.5.0 theorem was "atomic, *provided all closures voluntarily avoid retained access*" — a materially weaker claim than the record made, and "measureFns are trusted to behave" is not an acceptable hidden premise in the round about hostile inputs. (A bonus gap confirmed en route: abort errors carried no node attribution — `at: unknown`.)

**9. Closed with the audit's option 1: the authoritative World locks for the pass.** `law:maintenance.capability-confinement@1`: `world.lock()` returns a per-lock key; while held, `put`/`del`/`registerQuery` on the root refuse `world-write-during-maintenance`; the fork is born unlocked and stays writable; apply goes through `world.commit(key, fn)` — the *only* door, refusing forged keys (`world-lock-capability-refused`), with re-entrant locks refused (`world-already-locked`) and `finally` releasing on success, exception, quarantine, and cycle refusal alike. **Escaped writes become aborts, never corruption.** Independently, per the audit's requirement regardless of confinement: `passStartVclock` and the before-map are captured *before* topo, fork, or any user code — aborted and refused receipts now report the actual entry clock. And per-node execution tags escaping errors, so the witness aborts `at: "A"` with the refusal string in the reason.

**10. The scope of the law is stated, not smuggled.** `register`/`addGround` derive against the *live* world by design — they are not transactional, their writes are ordinary mediated transitions, and the grid says so (L-CONFINE-2's poisoned-query case had to be armed *after* registration for exactly this reason — the first draft leaked legitimately at `addGround` and falsified itself, recorded here). The audit's stronger option — executing derivations in a separate authority domain that structurally cannot reference the World object — is declared as the v-next in `maintenance.confinement.scope_note`, aligned with what portable/ic32 derivations need anyway.

**11. The batteries.** L-CONFINE-1 locks the witness verbatim post-fix: the write refuses, the pass aborts at `A`, the world is byte-untouched, the receipt reports the entry clock, and the lock releases. L-CONFINE-2 runs the matrix: composite `del`-escape, armed poisoned-*query* escape (fired inside `freshness`'s scope evaluation on the fork), and refresh-path escape each **abort with the world untouched**; an escape during *fresh replay-validation* is converted to a **quarantine** (`derivation-threw`) — the node is isolated, the pass completes, the world untouched; the lock survives cycle refusal; and the capability surface refuses forged commit, double lock, and wrong-key unlock. All twenty prior batteries re-ran green under the lock, `--check-receipt` green, negative battery **41/41** (including a case that strips the guard string from the world source and dies at grid_check's presence scan).

**The rhyme, in the audit's own phrasing, now three layers deep.** 8.1: state cannot change without World identity changing. 8.2: semantic support cannot be asserted without derivational evidence. 9.1: *computation inside a transaction cannot escape the transaction's authority boundary.* Grid v1.6.0 — 45 entries / 303 citations; kernel frozen at v1.0.2, untouched a fifth consecutive round.

## Round 9.2 — the master key was hanging on the object, exactly where the audit said to look

**12. The predicted follow-up was real, twice over.** GPT's note — *"the lock/capability itself must not be recoverable through a public property or public World method"* — described the shipped v0.6.0 precisely. `AUDIT-KEY-RECOVERY` (frozen in `probe_keytheft_v06_repro.mjs`): a retained closure read `world._lockKey` off the **public field** and committed *through* the lock — the leak landed mid-pass and the pass **did not even abort** (`aborted: false`, vclock 3→5). And the second half needed no key at all: `world.res` was a public Map, so `world.res.set("ghost", …)` planted a resource past every guard, silently — no put, no version discipline, no log entry. A beautiful confinement API with the key taped to the door and the wall missing beside it.

**13. Closed at the structure, not the convention.** v0.7.0: **all** World state moves into true private fields (`#res`, `#vclock`, `#log`, `#queries`, `#lockKey` — syntactically unreachable, immune to `Reflect`, enumeration, and prototype tricks); the key is **crypto-random** (`randomBytes(32)`), returned once by `lock()` and stored nowhere public; the read surface is copying (`vclock` getter, `log` returns dead copies — mutating the returned array provably changes nothing — `resourceEntries()` returns metadata copies); and both `World.prototype` and every **instance** are frozen, so method patching and instance shadowing throw under module strict mode. L-CONFINE-3 locks the theft witness (now dying at `world-lock-capability-refused` with a proper abort, world untouched, entry clock in the receipt) plus the sealed-internals matrix: no public state fields, zero own properties per instance, dead log copies, `vclock` assignment refused, both freezes asserted by attempted patching. All twenty-two prior batteries re-ran green on the sealed World; `--check-receipt` green; negative battery **43/43**, including two artifact-tamper cases (privacy marker stripped; prototype freeze stripped) dying at grid_check's construct scan.

**14. Where option 1's outer limit actually sits — stated in the grid.** A retained World reference now carries *no authority the transaction did not hand it*: writes refuse, the key is unreachable, the internals are sealed, the surfaces are frozen. What remains beyond this is the realm itself — a closure sharing the process can still, in principle, do things no object discipline prevents (patch *other* module bindings, exhaust resources) — and the record says so rather than implying otherwise: worker-domain isolation for derivations stays the declared v-next, aligned with what portable/ic32 execution needs regardless. The confinement law's evidence line now carries the full arc: falsified at the fork (9B), falsified at the key (9C), closed at the structure — with each witness frozen and each closure battery-locked.
