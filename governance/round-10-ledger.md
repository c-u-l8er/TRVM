## The verification ledger, round 10

**1. The two drops were merged into one tree, and the frozen pack verified before anything was trusted.** Lane A arrived as two directories — a v1.5-generation snapshot (which the ic32 pack was cut from, present twice, once redundantly nested) and the v1.7.1 head carrying rounds 9.1–9.3. The head supersedes the snapshot entirely; the final ic32 pack supersedes the one inside the snapshot (it gained `golden_sem_ids.json` and the §11 conformance ladder). The merged tree is v1.7.1 plus the final pack as a frozen subdirectory — **not** a file-level merge, because the pack's whole premise is that no mutable source is shared between the lanes. All seven pack files verified against their `MANIFEST.json` sha256s before use, and the pack's oracle is byte-identical to the working kernel (`80b8b0da…`), so the freeze is coherent rather than merely asserted. The superseded generation is archived, not deleted.

**2. `negative_battery.sh` claimed 44/44; a clean shell gave 43/44, and the missing case had never been able to run.** `run_case_engine` — the *only* case whose verifier is the world engine rather than grid_check — placed its scratch directory at `"$SCRATCH/$name"`, and `SCRATCH` appears exactly once in the script: at that use. Unset, the path resolved to the filesystem root, `mkdir -p` was refused, no `out.txt` was ever written, and the case reported `FAIL … wanted /support-mismatch/` — which reads as *the engine failed to catch a forgery*. It had not: reproduced by hand, the pruned-support receipt dies exactly as designed (`RECEIPT-CHECK: FAIL — ground replay refused: support-mismatch`, exit 1). A harness defect wearing an engine defect's diagnostic. `SCRATCH` is now named once, defaulted to the same root `run_case` already used, and a failed scratch is its own loud refusal rather than a confusing miss.

**3. The battery's printed total was hand-typed, and one of its cases had silently stopped forging anything.** Two repairs of the same species as item 2. The `44/44` was a literal in an `echo`; it is now derived from counters incremented where each verdict is actually decided, so the count cannot drift from the cases the way the published and printed law counts once did. And `version-lockstep-kernel` forged by `s.replace('const KERNEL_VERSION = "1.0.2";', …)` — a string literal that this round's bump would have turned into a **no-op**: the case would have copied the tree, changed nothing, watched grid_check pass, and reported a failure whose real cause was that it had stopped testing. It now matches the constant by pattern and **asserts that it forged something** before handing the tree to the checker. A falsifier that quietly falsifies nothing is worse than an absent one, because the roster still counts it.

**4. The kernel gains a module interface at 1.1.0 — additive, and the additivity is arithmetic rather than assurance.** The ic32 pack declared this Lane A's outstanding deliverable, and it was blocked on a structural fact: the kernel had **zero exports** and ran its entire battery, wrote its certificate, and called `process.exit` at module top level, so importing it was impossible in the only sense that matters. Everything below the CONFORMANCE marker is now guarded by `IS_MAIN`; importing the kernel has no side effects, mutates no artifact, and completes in 29 ms against minutes for the battery. The export surface carries `parse`/`extrude`, the runtimes, the digests, the canonical fold, and the two new signature entry points — and deliberately no setter, no mutation hook, nothing that would let an importer change what the oracle answers. **The proof that the calculus stayed frozen:** across the bump, `cert_id` is `a08ee15d…` before and after, `run_manifest_hash` is unchanged, and all **144 scheduler receipts are byte-identical**. The single certificate field that moved is `informational.node`, which no commitment covers.

**5. `stateDigest` is now *defined* as `sha256(stateSignature)` — one code path, so a published vector cannot drift from the digest it explains.** The signature computation was **extracted, not duplicated**. This is the whole difference between shipping bytes that are evidence and shipping bytes that are a second opinion: a parallel re-derivation would need its own correctness argument and could disagree with the hasher it claims to describe. There is nothing to disagree with — the digest is the hash *of* the vector. `semStateSignature` is the same relation one level up, over the canonically folded live heap (§3–§4), so `semStateId === sha256(semStateSignature)` holds by construction rather than by test.

**6. L-BYTES-1 asserts what a digest-level check structurally cannot.** 48/48 corpus states (initial *and* normal form for all 24 vectors) satisfy the preimage identity; the §5 compaction boundary is well-formed on every one of them (7 compacted to exactly 65 characters, longest uncompacted exactly **80** — a real corpus state sits precisely on the threshold, so the boundary is exercised by the corpus and not only by a synthetic probe); and **equivariance is asserted at the byte level** — alpha-variants and label permutations produce the *identical signature string*, not merely the same hash. That last clause is the row's reason to exist: a canonical form that agrees only *after* hashing would pass every digest-level equivariance check ever run against this kernel, and would teach ic32 the wrong canonical form while appearing conformant.

**7. The vectors carry three independent bindings, and each has its own executioner.** `golden_prehash_vectors.json` ships, per term, the canonical signature strings and ids for the initial and normal-form states, plus the compaction boundary. It binds: **(a)** every signature sha256s to its own `sem_state_id`; **(b)** every `normal_form.nf_id` equals the shipped refinement receipt's `nf_id` for that term, so the vectors cannot quietly describe a corpus the receipts never ran; **(c)** the compaction row states *what* was compacted, and the reconstructed pre-compaction string (84 characters, by §5's App rule over the previous nesting) must hash to the compacted signature the oracle emitted — **the reconstruction proves itself or extraction refuses**. grid_check v2.13 checks all three with no engine in sight; the extractor refuses to write at all if the oracle disagrees with shipped evidence. Five negative cases, each dying on a distinct diagnostic: a tampered signature (fails a), a signature *and* id moved together so they are internally consistent (only b catches it), a renamed term with the count intact (only the anchor catches it), a compaction reconstruction off by one character (fails c), and an over-threshold signature shipped uncompacted with a self-consistent hash (fails §5's structural rule). Each is resealed against `vectors_id` first, because a checker that only recomputes its own commitment proves nothing about whether the bytes describe this corpus.

**8. Gate.** Kernel PASS at v1.1.0 with L-BYTES-1 green; grid v1.8.0 — 46 entries / 320 citations across 14 artifacts; twenty-four world batteries green and `--check-receipt` green, both unchanged by this round; negative battery **49/49** with the engine-mode case executing for the first time; extractor deterministic across runs (`vectors_id 731b50b7…`, byte-identical output). The world layer was not touched.

## Theory movement this round

**Publishing a digest publishes a verdict; publishing its preimage publishes a *method*.** Every conformance target shipped so far has been a hash, and a hash is the one form of evidence that tells a failing implementation nothing about how it failed. ic32 could previously learn only that its canonical form was wrong — never where. The pre-hash bytes convert milestone #5 from a pass/fail oracle into a diff, which is the difference between a conformance suite and a debugger.

**The instruments were audited by the round that needed them.** Three of this round's findings (items 2, 3, and the `1.0.2` literal) are not about the calculus at all — they are about measurement apparatus that had stopped measuring while still reporting. The pattern is now familiar enough to name: **a falsifier's report of failure is itself a claim, and it can be wrong in the direction that flatters the engine.** The 44/44 was not a lie about the engine; it was a count that had quietly become a count of something else. Deriving totals and asserting that a forgery forged something are cheap; the alternative is a roster that grows while its coverage shrinks.

**One cross-runtime result, recorded because it will otherwise be rediscovered as a bug.** The shipped certificate was generated under node v22.22.2 and this tree runs v25.2.1. Re-running the kernel reproduces all 144 receipts and `cert_id` **exactly**, with `informational.node` the only differing field — a genuine determinism result across three major node versions. It also means the certificate's *file* sha256 changes whenever the oracle is run on a different runtime while nothing it commits to has moved. A file-hash comparison against the ic32 pack will therefore report "drift" on a tree that is provably identical where identity is defined; `cert_id` is the invariant, and the pack's manifest pins bytes.

**9. The pack is re-cut at v2, and v1 is left frozen rather than amended.** `ic32_handoff_v2/` carries the kernel at 1.1.0, the grid at 1.8.0, and `golden_prehash_vectors.json`, sealed under its own sha256 manifest and verified after sealing. v1 stays byte-intact and still verifies against its own manifest: "a drifted pack is not this pack" is the pack's own rule, so the honest move is a new version Lane B migrates to deliberately, not an edit to the object they were told was frozen. Four stale pointers in the inherited handoff text were corrected rather than carried — the oracle version in the mission paragraph, the milestone-5 target (digests → 48 byte targets), the lane summary that still named the module interface as future work, and the spec row's provenance note. The manifest also records the certificate's run-rewrite behaviour explicitly, so a Lane B session that runs the oracle and then re-verifies by file hash knows to check `cert_id` instead of concluding the pack drifted.

**Next:** CP5–CP7 via the module interface now that it exists — kernel-computation warrants whose witnesses are semantic films, unifying the two portable evidence objects; mechanically derived support (the grid's declared v4 question); and worker-domain isolation for derivations, the v-next standing since 9.2.
